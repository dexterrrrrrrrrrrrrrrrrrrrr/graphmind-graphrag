# Security and operational boundaries

- Keep the service private and loopback-bound. There is no end-user authentication or per-document authorization. The current API is unsuitable for public/multi-tenant exposure.
- Secrets come from server environment/.env only. Settings responses expose presence booleans, never keys or database passwords. Saved configuration metadata excludes credentials. Logs contain event IDs, types and timings; provider payloads and credential values are not logged.
- Uploaded bytes are untrusted. Extension/MIME checks, PDF signature checks, UTF-8 validation, body and chunk/page limits, UUID storage paths, and attachment-only downloads restrict handling. Malformed/encrypted/empty PDFs fail; OCR is not performed.
- The multipart body is bounded before spooling can grow without limit. File contents are also checked after reading. Nginx has an independent upload cap. Align its limit when changing the application limit.
- Parameterized Cypher handles all request data. Constant labels are generated only from hardcoded internal schema labels; semantic relationship types are allowlisted properties. There is no arbitrary query endpoint.
- Expansion forbids repeated nodes and bounds candidate entities, adjacency rows, depth, frontier size, output paths, and context. A high-degree graph can cause omitted evidence; limits do not imply complete search.
- Prompt instructions separate policy from JSON-encoded untrusted documents. Structured output, endpoint/evidence validation, quote checks, and ID checks reject invalid attributions. They cannot prove factual truth or eliminate prompt injection. A malicious model may still produce a claim not entailed by a valid quote. Review high-stakes answers against the displayed source.
- Live requests have timeouts and retry only transport errors, rate limits, and server errors; invalid/auth responses do not trigger paid retry loops. Ingestion fails explicitly and never fabricates facts or switches providers.
- Process-local rate limiting is appropriate for local development, not a distributed abuse-control system. Use a real gateway, authentication, quota accounting and worker isolation before deployment.
- Persist Neo4j volumes **and** the `.data` control-plane/source directory. Backups need a coordinated maintenance window. No distributed transaction spans Neo4j, SQLite and source files. Reprocessing is a replacement operation, so old evidence is unavailable until the new job succeeds.
- Deletion removes graph evidence, vectors, orphan entities, aliases no longer present, uploaded source files, and retained query/evaluation snapshots containing those sources. Data may remain in external backups, browser memory, downloads or provider logs according to their own retention policies.
- Use one backend worker. Durable metadata survives restart, but in-process tasks do not. Interrupted jobs are marked failed and require an explicit reprocess action; this prevents automatic paid provider retries.
- Integrity and TLS verification remain enabled in dependency/model installs, Docker builds and HTTPS provider calls. CPU PyTorch is selected on Linux. Managed proxy CAs are mounted rather than baked into image layers.
